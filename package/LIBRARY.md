# Media library — unpublished candidate 0.6.0

This replaces AUTO-MEDIA.md (0.4.1) and LOCAL-MEDIA.md (0.4.0). Use the package ZIP to upgrade; do not uninstall its children. No release/feed is published.

The upload area is labelled Where to upload files and Main media folder: this is the configured Media folder on hosting. Change upload folder selects a subfolder only when needed; otherwise uploads go to the main folder. The separate table filter affects visibility only, never upload destination. It offers All folders, Main media folder and each folder containing media (exact folder). Clicking Name/Size/Modified sorts both ways: locale-aware natural names and numeric sizes/timestamps, without extra network requests or dependencies. Default is name ascending. Rows move without losing copy controls.

Modified is filesystem mtime rendered by Joomla's date helper in the user's timezone. It is NOT an upload/addition timestamp: externally copied files may retain an old mtime. No added-at metadata table or inferred dates. Backend ambiguous-key rejection (409) is retained; ready-to-copy canonical rows no longer show unnecessary duplicate-stem warnings.

Components → BSL Media shows inline root/size settings to administrators, the current destination with Choose destination folder, one Upload files from computer button and one row per file: name, folder, format, readable size and Copy shortcode. No redundant key column, destination dropdown, Open folder or second upload confirmation. Root/limit are saved while preserving other params (including aliases/ACL); Options has only visible permission controls.

The root is a dedicated PUBLIC media folder: absolute Windows/Linux path or relative to JPATH_ROOT, e.g. ../media. It is not relative to the browser/computer or current PHP working directory. Empty/unreadable roots disable delivery; filesystem roots are rejected. The read-only folder picker is bounded to the parent of this Joomla site (site/siblings) or its configured media root, never a filesystem/drive root; picker navigation is limited to six levels. Other paths can be entered manually by the administrator. Escaping links are rejected.

Media/write destinations are limited to TWO subfolder levels below the media root. Both the page and destination dialog explicitly explain this with neutral Root / Section / Subsection / file labels; no thematic folders are created. One generic web dialog handles root or destination selection. Root browsing is admin-only; destination browsing is confined to the stored media root. Authorized creation is INSIDE the destination dialog, enters the new folder and is unavailable at depth two or during root selection. Creating a folder requires POST/action ACL/CSRF. Choosing a destination updates the page without reloading it.

Click Upload files from computer, select files with Ctrl/Shift/Ctrl+A and click the system dialog's Open: a normal multipart POST starts immediately. Cancelling sends nothing. There is one visible upload button; no second Upload confirmation. It is disabled while transfer starts, with status text; file input remains enabled so the files are included in POST. Folder-tree uploads are rejected. Server processing is sequential with per-file results, partial failures and detected PHP file-count truncation warnings. A request rejected before PHP cannot produce individual results. No resume/parallel/background queue/upload manager. JavaScript is required for the dialog and auto-upload.

The administrator sets a positive per-file value plus MB/GB selector. Decimal units: MB=1,000,000 bytes, GB=1,000,000,000 bytes; up to six decimal places. Publisher sees the configured allowance but cannot change it. Old max_upload_mb settings used binary units: their EXACT byte allowance is retained and shown converted to MB (legacy 64 becomes 67.108864 MB) until the administrator changes it. Value/unit/bytes are saved separately, retaining aliases/ACL. Unknown PHP/proxy limits can be stricter (per-file/POST/count/timeout); the application neither infers nor overrides hosting settings. Oversized/dropped-request/expired-token errors are explained.

Joomla ACL: core.manage for component/menu access, core.admin for settings/permissions/root browsing, media.create for subfolders, media.upload for uploads. Give Publisher component access plus chosen create/upload actions, not core.admin. No role is automatically granted rights. Each mutation checks POST, action ACL and CSRF on the server, independently of hidden controls. Options remains for permissions.

Uploads permit .mp3/.mp4/.opus (case-insensitive) with actual size and finfo/content screening: MP3 audio/mpeg, MP4 ISO BMFF ftyp, Opus OggS/OpusHead. Screening is not full codec decoding or antivirus. Executable secondary suffixes such as .php.mp4 are rejected. Uploaded-file provenance is checked in the controller. Traversal, invalid UTF-8, separators/control characters and Windows reserved device names are rejected for writes.

A unique hidden .tmp file is written in bounded chunks, checked, then published using a hard link: link fails if the final name exists. There is no overwrite-capable rename/move fallback. Hard-link support and web-PHP write permission are required for uploads; unsupported hosts fail closed with an explanation. Only our own unpublished temporary file is cleaned up on failure. Folder/file modes are 0750/0640 subject to hosting/umask. Read-only streaming still needs only read/traverse rights.

NO deletion, renaming, moving or overwriting exists for ANY role, including administrator. This is stated beside controls and in tooltips. Use a file manager/hosting panel for those operations. Administrator media are never deleted by extension uninstall. Keep root/parent directory writers trusted: portable PHP cannot guarantee race-free access against malicious concurrent directory replacement.

All MP3/MP4/Opus through depth two are public, independent of article ACL. Hidden/deeper/outside files are not discovered. Existing top-level full-name/unique-stem keys and saved aliases survive. Nested/Unicode/spaced names use deterministic media-HASH keys; external renaming/moving changes them. Nested additions do not change existing top-level aliases. Each row uses an unambiguous canonical key; duplicate top-level stems are explained beside the file instead of generating duplicate rows. Clipboard API has a selected-field fallback and an explicit failure message.

Public streaming remains GET/HEAD, one byte Range with exact 206/416 metadata, bounded 64 KiB reads, attachment download=1 and nosniff. Requires 64-bit PHP; proxy compression must not change lengths. Cache-Control no-store, no ETag/If-Range caching. Upload screening is additional; manually placed media remain trusted administrator content.
